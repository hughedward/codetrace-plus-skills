# Code Trace Plus（代码追踪小能手）：源码追踪阅读剧本

> **版本：0.1.0**（首个固化版；格式规范见 `references/format.md`，golden sample 见 `references/example-redisson.md`）

给一个入口（如 `redissonLock.lock()`）或一个问题（如"Redisson 看门狗怎么续期"），在**真实源码**里逐跳验证，产出一份 markdown 阅读剧本：用户拿着它在 IDE 里跟着走，它说点哪就 ctrl+点击哪，直到走完主线闭环。

## 硬性规则（违反任何一条即返工）

1. **只写真实读过的代码**：所有片段、行号必须来自本会话中用 grep/read 实际读取的源码。禁止凭记忆或想象写代码、编行号。
2. **声明版本**：文档开头写清入口和依赖版本，行号以该版本为准。依赖源码不在本地时，先下载对应版本 sources（如 Maven Central 的 `-sources.jar`）解压后再追，绝不拿别的版本行号凑数。
3. **主线优先，面试视角**：只追一条主线。筛子 = "面试官会问什么"——面试官不问的细节不抠，收进"支线速览"一行带过。
4. **跳转指令只能写成代码行内注释**，紧贴那一行：
   - `// ← 【点击】lock 跳转 本文件:103`（同文件）
   - `// p0006：【点击】renewLock 跳转 LockRenewalScheduler.java:56`（跨文件）
   - ctrl+点击会先落接口时补一句：`（先落接口，ctrl+alt+B 进实现）`
   - 有重载歧义时注明选哪个。
5. **线性调用禁止解释**："为什么能走到：xxx 调用的就是它"这类话是废话，一律不写。注释 + 点击跳转，结束。
6. **非线性 ≠ 断链**（这是本技能的灵魂）：lambda/回调/方法引用/@Override/抽象方法实现/定时器触发，同样要追成**连续的代码链**——来历说明里的每句话都必须落到真实 file:line。禁止出现"10 秒后 Netty Worker 线程到期触发"这类纯文字描述：Worker 在哪个类哪一行、怎么发现到期、怎么调到目标方法，都要能点击追到。具体要求：
   - 来历：这个对象/函数是哪一步传出去的（用 `pNNNN` 或 步骤编号回指），传递路径上每一站给 file:line
   - 身份：它实现/重写了谁的什么方法（接口或父类的 file:line）
   - 触发链：从"事件发生"到"调进目标方法"逐行追（如 定时器：入队 → 巡检循环 → 到期判断 → execute → task.run，每步真实行号）
   - 跨库不断：追进依赖源码（如 Netty 的 HashedWheelTimer）时，先取该依赖**同版本** sources，行号必须匹配
   - JDK 内部无法下钻时（如 CompletableFuture.whenComplete 语义），用"语义一句话 + 断点验证线程名"落地
   - 给出可亲手验证的锚点：断点位置 + 预期停下的线程名
7. **关键点击加 pNNNN 编号**（p0001 起全文递增），只标重要点击；后续步骤用它精确回指。
8. **不留半吊子结论**：任何结论式的话必须说完整——机制怎么实现的、和什么方案对比、代码锚点在哪。反例："看门狗是一个客户端一个 LockTask，不是每把锁一个定时器"（说完就完）。正例：接着说清"怎么做到的"——所有锁都走 `compareAndSet(null, new LockTask(...))` 复用同一对象、各锁往 name2entry 登记簿加一条、醒来把登记簿全部锁名拼进同一条批量 Lua；对比意义：1000 把锁也只有 1 个 Worker 线程、每轮 1 次 Redis 往返。要么说完整，要么删掉别提。
9. **闭环检测**：主线回到已出现过的编号/method → 显式标注"闭环"，主线终止。防无限递归。
10. **禁止悄悄换线程**：线程/时间跳变不是一种跳转类型，只出现在非线性来历说明和结尾总结图里。
11. **真实可验证**：每跳的 file:line 都必须能让用户在 IDE 里 ctrl+点击对上；对可疑的非线性触发点，给出可打断点验证的位置（"在 :170 打断点，加锁后 10 秒内必停"）。

## 每个 step 的格式模板

标题一行（最多两行，第二行只用于非线性副标题），编号三位数字进标题：

```markdown
#### ↓005、RedissonLock.java:185 一条 Lua 抢锁 + 成功回调

```java
185: private RFuture<Long> tryAcquireAsync(...) {
190:         ttlRemainingFuture = tryLockInnerAsync(...);  // p0004：【点击】tryLockInnerAsync 跳转 本文件:214
    .....                                              // 无关代码用 ..... 折叠
```

（代码块下方，按需：短解说 / `> **⚠️**：一句话+行号引用` / 非线性来历块 / `{会不会一直等？}` 式关键疑问及答案）
```

- 编号从 `001` 起，三位数字，不用 `step_` 前缀；正文和总结图里直接引用编号（"见 005"、"回到 011"）
- 标题里文件名:行号后面可以直接带一句话描述，不要在标题下再放单独的标题行
- **顺序固定：标题 → 代码块 → 说明**。任何说明（含非线性来历块）都放代码块下方，不得插在标题和代码块之间

## 工作流

1. **定位入口**：确认用户给的入口/问题与源码位置（当前目录、指定路径、或需下载 sources）。grep/read 找到真实入口 file:line。
2. **逐跳追踪循环**：读真实源码 → 摘 5~15 行关键片段（真实行号，无关行折叠为 `.....`）→ 下一跳写成行内【点击】注释 → 线性跳直接过，非线性跳**同样逐行追成链**（含换库、换线程的触发路径），追不动的地方给断点验证锚点。
3. **闭环或自然终止**：回到已访问节点标注闭环；返回值/异常出口算自然终止。
4. **收尾三件套**：
   - 全程一条线总结：ASCII 流程图，节点用编号（001 这种），线程接力用分隔线画（`─┐ │ 10秒 ┌─...`），闭环用箭头标出
   - 支线速览：一行一条，带 file:line，注明"面试追问才展开"
   - 面试问答（QA）：从追踪主线里提炼 6~9 个面试官真会问的问题（如"指定 leaseTime 还有看门狗吗""续期前为什么 hexists""哪个线程在续期"），每条答案 2~4 句话并回引编号/行号，不引入主线没追过的内容
5. **落盘**：中文写入 `trace/<主题>.md`。
