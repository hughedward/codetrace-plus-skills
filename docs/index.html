Why a "script", not a "tutorial"

Ordinary source-code explainers make you memorize lore. Every step of a Code Trace Plus script is an action you physically perform in the IDE.

Real line numbers, never invented

Every hop comes from grep / read of real source against a pinned dependency version — each one ctrl+click-verifiable in IDEA. Even dependency libraries (Netty) are read from same-version sources.

Jumps as inline comments

The next hop sits right next to the code: // 【click】tryAcquire → this file:152. Just follow along. Zero filler for linear calls.

pNNNN precise back-references

Key clicks are numbered (p0009); later steps point back to "which line this this came from" — the cure for losing track of who calls whom.

Non-linear ≠ broken chain

Timers, callbacks, overrides, thread switches, cross-library hops — all traced as a continuous clickable chain: enqueue → patrol → expiry → task.run(this), line by line.

Loop closure is the finish line

When the main line returns to where it started, the trace closes. The ending "one-line summary" diagram shows every thread relay at a glance.

Interview-grade QA

The main line is filtered by "what would an interviewer actually ask". The script ends with Q&As whose answers cite step numbers and line numbers.

How it works

You provide an entry point or a question. It does the rest.

Give an entry

"Trace redissonLock.lock(), entry at IndexController.java:42" — or simply ask "how does the watchdog renew the lock?".

It verifies hop by hop

grep / read real source; snippets with real line numbers each hop. If source isn't local, it fetches the same-version -sources.jar. Never writes from memory.

You click along

It writes trace/<topic>.md. Open it in a split view and ctrl+click wherever it says, until the loop closes.
